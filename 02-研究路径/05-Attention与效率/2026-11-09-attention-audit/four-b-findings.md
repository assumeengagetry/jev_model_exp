## Most useful direct causal examples

- Nox4B: `_masks` explicitly constructs `.tril()`; its tree implementation also retains causal prefix and suffix rows.
- Mapika decider4B: engine documents causal layers; Sieve4B has bidir=False defaults, not its optional bidir capability.
- Kev4B/NeoHorse: their Qwen3.5 path runs each question as a causal continuation row; the phrase block-causal in generic code is not block-bidirectional.
- KnowLine4B Gen5.5: author explicitly says with causal attention and repeats the full input. On the second copy, the first copy of the question is already to its left, so state tokens can now be computed using that question while the mask remains causal.

## Block variants are materially different

- Cerno: state is one block; each question+options is another; within-block bidirectional and cross-block causal.
- Verdin: state chunks of 8192 tokens become bidirectional internally; question branches remain causal.
- PurpleMIST Mini2.0: prefix causal; later question region bidirectional.
- Saif4B: state prefix and each question block bidirectional; question blocks see prefix and remain isolated from each other. This is not plain global full-bidi and not merely a sequence of causally ordered blocks.

## Further distinctions

- Nari has a causal backbone plus a separate candidate-interaction head. Candidate attention in the head does not make Qwen backbone bidirectional.
- Amber Hybrid mixes two models: causal Qwen decoder and bidirectional ModernBERT encoder.
- OneJev1.6 does not enable the newer Flide block-bidi overrides. Mere framework support does not identify a checkpoint mask.
