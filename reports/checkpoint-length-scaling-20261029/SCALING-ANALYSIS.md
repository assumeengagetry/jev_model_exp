# 把长度benchmark用于配置选择

## 显存随输入长度和物理batch怎样变化

用本轮固定长度和物理batch8/16/32的实测值拟合，M的单位为GiB：

- B = 单次同时驻留GPU的sequence条数。
- L = padding之后的单条sequence长度。
- x = B × L / 16384。
- y = (B / 16) × (L / 1024)²。

| 开关 | 峰值allocated显存计算式 | 拟合RMSE GiB |
|---|---|---:|
| On | M ≈ 1.243 + 2.412 × x | 0.015 |
| Off | M ≈ 1.266 + 31.291 × x | 0.011 |

这里的常数项对应模型与梯度的固定开销；x项对应随总驻留tokens增长的开销；y项对应随单条长度平方增长的开销。计算时使用物理microbatch，而不是梯度累计之后的有效batch。

## 开启checkpointing付出的时间

| sequence tokens | On前向 / 反向 秒 | Off前向 / 反向 秒 | On总体耗时 / Off总体耗时 |
|---|---:|---:|---:|
| 256 | 0.150 / 0.320 | 0.115 / 0.136 | 1.83× |
| 512 | 0.156 / 0.386 | 0.166 / 0.235 | 1.34× |
| 1,024 | 0.304 / 0.774 | 0.311 / 0.467 | 1.37× |
| 2,048 | 0.612 / 1.592 | 0.639 / 0.962 | 1.37× |
| 4,096 | 1.291 / 3.406 | OOM | — |
| 8,192 | 2.878 / 7.824 | OOM | — |

前向/反向采用CUDA events计时，每行对应累计32条sequence；反向包含checkpoint触发的重算。总体耗时另含拼batch和H2D。

## 换任务、batch或显卡时怎么选

1. 先统计每个物理microbatch的最大长度及padding。不同文本内容先换算成tokens，不使用字数代替。
2. 以B和补齐后的L查主报告的实测表；使用上面的计算式估算其他组合。
3. 以主报告中的reserved峰值加上CUDA进程开销，对照目标GPU显存容量。
4. 想保持有效batch又降显存，降低物理microbatch并增加梯度累计。
5. 换模型时，用同一脚本测几档长度后重新拟合；模型层数、隐藏维度、精度和attention算子一并记下。
